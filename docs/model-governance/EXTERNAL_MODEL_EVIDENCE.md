# External Model Evidence

Status: accepted lower-precedence evidence protocol for ordinary governance 0.3.18.

## Purpose

This surface imports a small, reproducible public benchmark prior for the current model
library without creating a second routing authority. The only v1 source is the official
`LiveBench/new-livebench` GitHub repository.

The accepted evidence is useful for qualification priority, matched-trial priority, and
a lower-precedence tie-break when higher governance rules already permit a choice. It
does **not** qualify a model, bypass an existing qualification/risk ceiling, promote or
demote a production route, change a running Task, or replace internal calibration.

## Authority and precedence

`config/MODEL_REGISTRY.yaml` remains the model-library and qualification boundary.
`config/MODEL_ROUTING.yaml` remains the routing authority.

Selection precedence is:

1. exact Task override;
2. project-local calibration;
3. governance calibration snapshot;
4. accepted external benchmark evidence;
5. bootstrap routing seed.

The evidence file is therefore data used by the existing routing authority, not an
authority plane of its own. When materially relied upon, a Task or Lead decision cites
the exact accepted repository commit containing `config/EXTERNAL_MODEL_EVIDENCE.yaml`.
A later evidence refresh never retroactively changes an already activated Task or
decision.

## Source and identity

The source contract is `config/EXTERNAL_MODEL_EVIDENCE_SOURCE.yaml`. v1 has exactly one
provider/source and four explicit internal-to-source mappings:

- `gpt-5.6-sol` -> `gpt-5.6-sol-max`
- `gpt-5.6-terra` -> `gpt-5.6-terra-max`
- `gpt-5.6-luna` -> `gpt-5.6-luna-max`
- `gemini-3.7-flash` -> `gemini-3.7-flash-high`

Every mapping is tagged `compatible_prior`: the public harness/effort configuration is
useful evidence but is not asserted to be identical to every governed runtime or
reasoning configuration under the internal semantic key. The updater never enrolls
unknown models and never guesses a replacement mapping from a similar name.

The initial 0.3.18 candidate is pinned to the exact LiveBench commit, table blob and
categories blob declared in the source contract. Future refreshes first pin the current
LiveBench `main` to an exact commit, then select the latest date for which both a table
and categories file exist at that exact commit.

## Bounded v1 coverage

v1 is deliberately a broad prior rather than a benchmark warehouse. It stores one
static LiveBench source-native task score for each of the seven source groups, for each
of the four frozen model mappings: 28 logical observations total.

The exact representative tasks are part of the accepted source contract:

- Agentic Coding -> `python`
- Coding -> `code_generation`
- Data Analysis -> `tablejoin`
- IF -> `summarize`
- Language -> `connections`
- Mathematics -> `math_comp`
- Reasoning -> `theory_of_mind`

Refresh may update the values and provenance for those fixed tasks, but it may not
choose different representatives merely because upstream data changes. If a selected
task disappears, moves to a different source group, or becomes ambiguous, refresh
fails closed and leaves accepted evidence untouched. Expanding or changing the
representative set requires a new governance Task or an explicit exact-revision
re-anchor.

No category mean, category rank, locally recomputed overall score, or cross-site
composite is accepted.

## Accepted representation

`config/EXTERNAL_MODEL_EVIDENCE.yaml` is JSON-compatible YAML generated by the Python
standard library. This intentionally avoids an extra YAML dependency and gives
deterministic serialization.

`observation_columns` defines the logical fields and `observation_rows` stores the
values column-wise to avoid repeating field names for every source-native task score.
Each logical observation still contains exactly:

`model_key`, `source_model_label`, `benchmark_group`, `benchmark`,
`source_native_metric`, `benchmark_or_methodology_version`, `source_ref`, and
`model_identity_match`.

A LiveBench release/methodology change forms a new evidence series; it is not silently
compared as if it were the same measurement series.

`collected_at` is provenance only. Material comparison excludes that timestamp and
canonicalizes row ordering, so timestamp/order/format-only noise cannot create an
update candidate.

## Refresh behavior

`.github/workflows/external-model-evidence.yml` provides:

- pull-request validation with read-only repository permission;
- a monthly refresh check;
- manual `workflow_dispatch`.

The refresh path is fail-closed. Network failure, missing exact mapped rows, ambiguous
identity, source schema drift, selected-task drift, or format drift leaves the
previously accepted evidence untouched.

If an open PR carrying `[MODEL-EXTERNAL-EVIDENCE-UPDATE-v1]` already exists, the
scheduled/manual job exits before generating or mutating a candidate. Otherwise, a
material source change creates a unique automation branch and a normal PR. There is no
automatic merge, no automatic qualification, no `MODEL_REGISTRY` edit, no automatic
`MODEL_ROUTING` preference/status edit, and no third-party bot or service.

The public source requires no private credential. The workflow may use only GitHub's
repository-provided `GITHUB_TOKEN` for repository write/PR operations.

## Security and simplicity

External source content is data only. The updater never executes source-provided code,
instructions, URLs, plugins, or adapters. v1 has no provider framework, crawler,
database, daemon, adopter registry, live service, or second authority store.

Ordinary conformance remains offline/read-only. External network access is confined to
the dedicated updater/Actions workflow and is not added to the governance conformance
checker.
